## 4. 静态页面承载判断

| 能力 | 是否适合静态承载 | 判断 |
|------|------------------|------|
| 5-8 分钟主体验路径 | 是 | 可由静态场景配置、浏览器状态、SVG/CSS/Web Audio 承载。 |
| 地图显影、压力反馈、镜头节奏 | 是 | 第一阶段可使用轻量 SVG/CSS/Canvas，不需要 GIS SDK。 |
| 一条关键证据阅读 | 是 | 只读引用证据 ID，进入阅读模式后回到现场即可。 |
| 退朝案牍 | 是 | 本地生成体验产物，不写入证据包和历史 Claim。 |
| 退朝后轻量探索入口 | 是 | 图谱、透镜、关系图可先作为折叠入口或静态视图。 |
| 多历史题材复用 | 否，暂不做 | 需要更通用的 Scene DSL 和内容管理，不属于第一阶段。 |
| 跨设备保存、账户、分享 | 否，暂不做 | 会引入后端状态和权限边界，不属于静态纵切片。 |
| React/Vite/TypeScript 迁移 | 暂不触发 | 先做模块化静态前端；达到触发条件后再另开任务。 |

结论：**静态页面能够承载第一阶段，但必须从“单页脚本堆功能”转为“配置 + 状态 + 事件 + 呈现”的模块化静态前端。**
